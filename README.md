# RentTech: клиентский портал

Клиентская часть веб-сервиса аренды промышленной и бытовой техники. Проект выполнен на Vite, HTML, CSS и vanilla JavaScript. Сайт содержит ровно пять страниц и два адаптива (ПК и телефон). Ниже приведен развернутый текст по критериям курсовой работы.

## 1. Анализ предметной области

Аренда техники используется в строительстве, логистике, клининге, ремонте и бытовых задачах. Клиенту важно быстро найти нужную позицию, понять доступность и оформить заявку без долгих согласований. Для бизнеса критичны прозрачные условия, контроль статусов и оперативная коммуникация.

Типовые роли:

- клиент (заказчик аренды);
- оператор/менеджер (обрабатывает заявки и координирует доставку);
- поставщик/склад (обеспечивает выдачу техники).

Типовые процессы:

- выбор оборудования по категории и назначению;
- проверка наличия и ориентировочной цены;
- оформление заявки с датами и адресом;
- подтверждение заказа и организация доставки/самовывоза.

## 2. Обоснование выбора стека

Использованный стек не превышает требования и соответствует учебным целям:

- HTML5 применяется для семантической разметки пяти страниц;
- CSS3 отвечает за визуальную композицию, сетку и адаптив;
- JavaScript (ES6+) реализует фильтры, обработку форм и интеграцию API;
- Vite обеспечивает быстрый dev‑сервер, сборку и корректную работу многостраничного приложения;
- JSON используется как формат хранения данных техники;
- Git фиксирует историю разработки.

Данный стек прост, надежен и хорошо документирован, что важно для курсовой работы.

## 3. Архитектура и структура проекта

Проект состоит из пяти HTML‑страниц:

- Главная: [index.html](index.html)
- Каталог: [catalog.html](catalog.html)
- Карточка техники: [equipment.html](equipment.html)
- Бронирование: [booking.html](booking.html)
- Контакты: [contacts.html](contacts.html)

Ключевые файлы:

- Логика и работа с данными: [src/main.js](src/main.js)
- Стили и адаптив: [src/style.css](src/style.css)
- Данные техники (JSON): [public/data/equipment.json](public/data/equipment.json)
- Многостраничная сборка: [vite.config.js](vite.config.js)

Стили организованы по блокам интерфейса (header, карточки, формы, секции), что упрощает поддержку и развитие.

## 4. Визуальная концепция и UI

Визуально сайт ориентирован на деловую аудиторию: чистые карточки, заметные CTA‑кнопки, читаемая типографика, спокойные цветовые акценты. Главная страница формирует доверие к сервису и ведет к ключевым действиям — каталогу и бронированию.

## 5. Реализация функционала

Функциональность клиентской части включает:

- каталог с фильтрацией по категории и доступности;
- детальную карточку выбранной техники;
- форму бронирования с отображением сводки заявки;
- переключение валют для просмотра цен;
- сохранение выбранной валюты между страницами.

Вся логика сосредоточена в [src/main.js](src/main.js) и инициализируется на каждой странице.

## 6. Интеграция внешнего API

Добавлен внешний API курсов валют:

- источник данных: https://open.er-api.com/v6/latest/RUB
- получаемые курсы: RUB, USD, EUR;
- цены автоматически пересчитываются на главной странице, в каталоге и на карточке техники;
- валюта сохраняется в localStorage.

Таким образом демонстрируется использование стороннего API и обновление интерфейса в реальном времени.

## 7. Адаптивная верстка

В проекте предусмотрены два адаптива:

- ПК (desktop) — многоколоночные сетки, широкие карточки, компактная шапка;
- телефон (mobile) — одна колонка, раскрывающаяся навигация, переразметка секций.

Адаптив реализован через media‑запросы и гибкие размеры.

## 13. Подробное описание файловой структуры

### 13.1 Корневые файлы

**`index.html`** — главная страница проекта. Содержит hero-блок с заголовком и двумя CTA-кнопками («Смотреть каталог» и «Оформить заявку»), секцию с тремя карточками избранной техники, блок преимуществ сервиса («Быстро», «Надёжно», «Удобно»), блок со статистикой (количество единиц техники, клиентов, лет работы) и футер с контактами. Карточки техники на главной генерируются динамически из JSON-данных, что позволяет отображать актуальные цены с учётом выбранной валюты.

**`catalog.html`** — страница каталога. Содержит панель фильтров (по категории и статусу доступности) и сетку карточек. Карточки отрисовываются через JavaScript из массива данных. При изменении фильтров список обновляется без перезагрузки страницы. Каждая карточка содержит название техники, краткое описание, цену в сутки, статус доступности и кнопку «Подробнее».

**`equipment.html`** — страница детальной карточки конкретной единицы техники. Получает идентификатор позиции через query-параметр `?id=` в URL. На основании этого id находит нужный объект в массиве и отображает полную информацию: название, описание, характеристики, цену, статус, а также блок сервисных условий (доставка, страховка, минимальный срок аренды). Кнопка «Забронировать» передаёт id и название техники на страницу бронирования.

**`booking.html`** — страница оформления заявки. Содержит форму с полями: ФИО, номер телефона, выбранная техника (автозаполняется из query-параметра), даты начала и окончания аренды, адрес доставки, комментарий. Рядом с формой расположена сводка заявки, которая обновляется в реальном времени по мере заполнения полей. После отправки формы пользователь видит сообщение об успешной отправке с указанием ориентировочного времени подтверждения.

**`contacts.html`** — страница с контактной информацией. Содержит реквизиты компании (телефон, email, адрес, режим работы), блок-заглушку вместо карты (реализована без сторонних API), а также секцию FAQ с ответами на часто задаваемые вопросы об условиях аренды, страховке, продлении срока и работе с оператором.

### 13.2 Исходный код

**`src/main.js`** — единственный файл с JavaScript-логикой. Код разделён на функциональные блоки, каждый из которых инициализируется только на соответствующей странице. Ниже описаны ключевые функции.

`loadRates()` — асинхронная функция, выполняющая запрос к API курсов валют `open.er-api.com`. Сохраняет полученные курсы в переменную и передаёт их во все функции, работающие с ценами. При ошибке запроса устанавливает резервные курсы, чтобы интерфейс оставался рабочим.

`formatPrice(priceRub, currency, rates)` — функция форматирования цены. Принимает базовую цену в рублях, выбранную валюту и объект курсов. Возвращает строку с пересчитанной ценой и символом валюты. Для рублей округление без копеек, для USD и EUR — два знака после запятой. Использует `Intl.NumberFormat` с локалью `ru-RU`.

`renderCards(container, items, currency, rates)` — функция генерации HTML-карточек. Принимает DOM-элемент контейнера, массив объектов техники, выбранную валюту и курсы. Формирует HTML-строку через `map()` и вставляет в контейнер через `innerHTML`. Применяется как на главной странице (первые три позиции), так и в каталоге (с фильтрацией).

`applyFilters()` — функция фильтрации каталога. Считывает текущие значения селектов категории и статуса, фильтрует исходный массив через `filter()` и передаёт результат в `renderCards()`. Вызывается по событию `change` на обоих селектах.

`initEquipmentPage()` — инициализация страницы детальной карточки. Считывает `id` из `URLSearchParams`, находит объект в массиве по совпадению, заполняет DOM-элементы страницы данными найденного объекта. Если `id` не передан или не найден — отображает первую позицию из массива.

`initBookingPage()` — инициализация страницы бронирования. Считывает из `URLSearchParams` `id` и `name` техники, подставляет значение в поле формы. Навешивает обработчики `input` и `change` на все поля формы для обновления сводки заявки. Обрабатывает событие `submit` формы: блокирует стандартное поведение, скрывает форму и показывает сообщение об успехе.

`initCurrencySelector()` — инициализация переключателя валют. Считывает сохранённое значение из `localStorage`, устанавливает его в селект, запускает пересчёт цен. При изменении значения селекта сохраняет выбор в `localStorage` и повторно вызывает `renderCards()` с новой валютой.

`initMobileMenu()` — инициализация мобильного меню. Навешивает обработчик клика на кнопку-гамбургер, переключает CSS-класс на навигационном блоке. При клике на любую ссылку меню автоматически закрывает список.

---

**`src/style.css`** — единый файл стилей для всего проекта. Организован по блокам интерфейса:

- `:root` — CSS-переменные для цветовой палитры, отступов и радиуса скругления;
- `reset` — сброс браузерных стилей;
- `header` — фиксированная шапка с логотипом, навигацией и переключателем валют;
- `hero` — hero-секция главной страницы с фоновым градиентом;
- `cards` — сетка карточек техники (CSS Grid, 3 колонки на десктопе);
- `card` — стили отдельной карточки: тень, скругление, эффект при наведении;
- `badge` — метка статуса доступности (зелёная / красная);
- `filters` — панель фильтров каталога;
- `equipment-detail` — двухколоночный макет страницы детальной карточки;
- `booking` — двухколоночный макет страницы бронирования (форма + сводка);
- `form` — стили полей ввода, лейблов, кнопок;
- `summary` — блок сводки заявки;
- `footer` — подвал с контактами и копирайтом;
- `@media (max-width: 768px)` — мобильный адаптив: одна колонка, раскрывающееся меню, переразметка форм и карточек.

### 13.3 Данные

**`public/data/equipment.json`** — массив объектов, каждый из которых описывает одну единицу техники. Структура объекта:

```json
{
	"id": "001",
	"name": "Перфоратор Bosch GBH 2-26",
	"category": "household",
	"status": "available",
	"pricePerDay": 450,
	"description": "Мощный перфоратор для сверления и долбления в бетоне и кирпиче.",
	"specs": {
		"power": "800 Вт",
		"weight": "2.8 кг",
		"modes": "сверление, удар, долбление"
	}
}
```

Поле `category` принимает значения `industrial` (промышленная техника) или `household` (бытовая техника). Поле `status` принимает значения `available` (свободно) или `busy` (занято). Цена хранится в рублях — пересчёт в другие валюты выполняется на стороне клиента при каждом рендере. Файл можно редактировать напрямую без изменений в HTML или JS: скрипт автоматически отрисует карточки из актуального массива.

### 13.4 Конфигурация сборки

**`vite.config.js`** — конфигурация сборщика Vite для многостраничного приложения. В секции `build.rollupOptions.input` перечислены все пять HTML-файлов как точки входа. Это обеспечивает корректную сборку каждой страницы в отдельный файл в папке `dist` и сохраняет работоспособность внутренних ссылок в production-окружении.

**`package.json`** — файл зависимостей проекта. Единственная зависимость в `devDependencies` — это Vite. Других пакетов нет, что минимизирует размер `node_modules` и ускоряет установку.

## 14. Описание пользовательских сценариев

### Сценарий 1: Поиск и бронирование техники

1. Пользователь открывает главную страницу, видит hero-блок с описанием сервиса.
2. Нажимает кнопку «Смотреть каталог» — переходит на `catalog.html`.
3. В каталоге выбирает фильтр по категории «Промышленная» — список обновляется.
4. Находит нужную позицию, нажимает «Подробнее» — открывается `equipment.html?id=003`.
5. Читает характеристики, нажимает «Забронировать» — переходит на `booking.html?id=003&name=...`.
6. Заполняет форму: ФИО, телефон, даты, адрес.
7. В блоке сводки видит итог заявки в режиме реального времени.
8. Нажимает «Отправить заявку» — видит сообщение об успешной отправке.

### Сценарий 2: Просмотр цен в другой валюте

1. Пользователь открывает любую страницу с карточками техники.
2. В шапке находит переключатель валют, выбирает USD.
3. Цены на всех карточках мгновенно пересчитываются по актуальному курсу.
4. Пользователь переходит на другую страницу — валюта сохранена, пересчёт применяется автоматически.

### Сценарий 3: Использование с мобильного устройства

1. Пользователь открывает сайт на смартфоне.
2. Шапка перестраивается: логотип слева, кнопка меню справа.
3. При нажатии на кнопку меню раскрывается список навигации.
4. Сетка карточек отображается в одну колонку.
5. Форма бронирования и сводка заявки располагаются вертикально.

## 15. Описание UI-компонентов

**Карточка техники** — переиспользуемый визуальный блок. Содержит: заголовок с названием позиции, краткое описание (одна-две строки), цену за сутки в выбранной валюте, цветной бейдж статуса доступности, кнопку перехода на детальную страницу. На hover — лёгкое поднятие карточки через `transform: translateY` и усиление тени.

**Бейдж статуса** — небольшой элемент в правом верхнем углу карточки. Зелёный цвет и текст «Свободно» для доступной техники, красный и «Занято» для недоступной. Позволяет пользователю с первого взгляда оценить доступность позиции.

**Панель фильтров** — два выпадающих списка: по категории (Все / Промышленная / Бытовая) и по статусу (Все / Свободно / Занято). Фильтры работают в связке: применяются одновременно при каждом изменении любого из них.

**Переключатель валют** — компактный `<select>` в правой части шапки. Содержит три варианта: RUB, USD, EUR. Сохраняет выбор пользователя между сессиями через `localStorage`. На мобильных устройствах элемент оптимизирован по размеру для пальцевого ввода.

**Сводка заявки** — блок на странице бронирования, расположенный справа от формы (на мобильном — под формой). Отображает: выбранную технику, период аренды (количество дней), ориентировочную стоимость, адрес доставки. Обновляется в реальном времени по мере ввода данных в форму.

**Мобильное меню** — скрытый по умолчанию список навигационных ссылок. Открывается по нажатию на кнопку-гамбургер в шапке. Закрывается при повторном нажатии или при переходе по любой ссылке. Реализовано переключением CSS-класса без сторонних библиотек.

## 16. Технические решения и обоснования

**Почему vanilla JS без фреймворков.** Задание предполагает изучение базовых технологий веба. Использование React или Vue создало бы избыточную сложность для проекта с пятью статическими страницами и минимальной интерактивностью. Vanilla JS позволяет явно видеть работу с DOM, события и асинхронные запросы без абстракций.

**Почему Vite, а не просто HTML-файлы.** Vite обеспечивает hot module replacement при разработке (изменения применяются без перезагрузки страницы), минификацию JS и CSS при сборке, а также корректную обработку импортов. Это приближает процесс разработки к реальным проектам.

**Почему данные в JSON, а не захардкожены в HTML.** Вынос данных в отдельный файл разделяет логику и представление. Добавление новой позиции требует только редактирования JSON — HTML и JS изменять не нужно. Такой подход демонстрирует базовый принцип работы с данными, аналогичный работе с API.

**Почему localStorage для валюты.** Сохранение выбора пользователя между страницами без серверной части возможно только через `localStorage`. Альтернатива — передача значения через query-параметры в каждой ссылке — значительно усложнила бы навигацию и генерацию ссылок.

**Почему fallback при ошибке API.** Внешний API курсов валют может быть недоступен по техническим причинам. Обработка ошибки через `try/catch` с резервными курсами гарантирует работоспособность интерфейса независимо от доступности внешнего сервиса. Это важная практика при работе с любыми внешними зависимостями.

**Почему карта-заглушка на странице контактов.** Интеграция Google Maps или аналогичного сервиса требует API-ключа, регистрации и потенциально платной подписки. Для учебного проекта это избыточно. Заглушка визуально выполняет ту же роль, не добавляя внешних зависимостей.

## 17. Возможные направления развития проекта

Проект спроектирован так, что его можно расширять без кардинальных изменений архитектуры.

**Подключение backend-части.** Форма бронирования готова к интеграции с сервером: достаточно заменить заглушку в обработчике `submit` на `fetch`-запрос к API. Данные формы уже собраны в объект и готовы к сериализации.

**Переход на динамические данные.** Функция `renderCards()` принимает массив данных как параметр. Чтобы загружать данные с сервера вместо локального JSON, достаточно заменить источник данных — остальной код останется без изменений.

**Добавление личного кабинета.** Страницы авторизации и регистрации можно добавить как новые HTML-файлы с соответствующими точками входа в `vite.config.js`. Логика авторизации — через JWT-токены в `localStorage`.

**Расширение каталога.** Новые позиции техники добавляются редактированием `equipment.json`. Можно добавить новые поля (например, фотографии, склад, рейтинг) — для их отображения достаточно обновить функцию `renderCards()`.

**Добавление поиска по каталогу.** Текстовый поиск реализуется как дополнительный фильтр: поле ввода + фильтрация массива по полям `name` и `description` через `includes()`. Логика встраивается в существующую функцию `applyFilters()`.

**Интеграция реальных карт.** На странице контактов заглушку можно заменить на iframe с Яндекс.Картами (без API-ключа) или Leaflet.js с OpenStreetMap (полностью бесплатный вариант).

## 19. Использование ООП в проекте

В проекте применены элементы объектно-ориентированного подхода без избыточного усложнения архитектуры. ООП используется точечно — только там, где это действительно упрощает поддержку кода и работу со связанным состоянием. Такой подход позволил добавить объектную структуру, не превращая проект в сложную фреймворк-архитектуру.

**`CurrencyService`** отвечает за работу с валютами:

- хранит текущую выбранную валюту и курсы;
- загружает курсы через внешний API;
- форматирует цены в нужной валюте;
- сохраняет выбор пользователя в `localStorage`;
- инкапсулирует логику, связанную именно с валютными операциями, чтобы она не распылялась по всему файлу.

**`PageState`** используется для хранения состояния страниц:

- данные каталога;
- данные карточки техники;
- данные главной страницы.

Это упрощает управление состоянием и делает код более читаемым: вместо набора разрозненных глобальных переменных используется один объект, который хранит данные по страницам и позволяет обновлять интерфейс централизованно.

Использование классов позволило отделить состояние и бизнес-логику от функций рендеринга, сделать код более структурированным и показать применение ООП на практике. В результате в проекте появились признаки объектного подхода: есть классы, их свойства, методы, инкапсуляция логики и понятное разделение ответственности между компонентами приложения.

## 20. Использование методологии БЭМ

В проекте используется методология БЭМ для именования классов и организации компонентов интерфейса. Это повышает читаемость кода, упрощает поддержку и делает структуру стилей более предсказуемой. БЭМ особенно удобен в многостраничном проекте, потому что один и тот же интерфейсный блок можно одинаково использовать на разных страницах без риска конфликтов в стилях.

БЭМ-классы применены к основным блокам интерфейса:

- шапка сайта — `site-header`, `site-header__brand`, `site-header__nav`, `site-header__currency`;
- hero-блок — `hero__copy`, `hero__actions`, `hero__stats`, `hero__panel`;
- каталог — `catalog-card`, `catalog-card__tag`, `catalog-card__title`, `catalog-card__status`;
- страница техники — `detail__hero`, `detail__panel`, `detail__grid`, `detail__card`;
- форма бронирования — `booking-form`, `booking-form__field`, `booking-form__control`, `booking-summary`;
- контакты и FAQ — `contact-card`, `faq__item`, `faq__summary`;
- подвал — `site-footer__column`, `site-footer__brand`.

Структура БЭМ в проекте построена по принципу «блок — элемент — модификатор». Например, `site-header` является блоком, `site-header__nav-link` — его элементом, а `site-header__nav-link--active` — модификатором активного состояния. Аналогично устроены карточки техники, форма бронирования, блоки FAQ и карточки контактов.

При этом старые классы оставлены в верстке как резервные, чтобы не нарушить текущую визуализацию и обеспечить безопасный переход на БЭМ без поломки интерфейса. Это позволило постепенно внедрить новую структуру без полной переработки всех стилей и без риска сломать текущую сборку проекта.
